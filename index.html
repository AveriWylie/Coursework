Algorithm Analysis

Empirical complexity harness written alongside the algorithm analysis course. It times an implementation across a wide range of input sizes, fits the measured runtimes against candidate growth models from O(1) through O(n³) by least squares, and ranks them by R², so the asymptotic class of a piece of code is recovered from data instead of asserted from the source. Used against merge sort and binary search written from scratch, as a check on the analysis done by hand.

(n²-1)-Puzzle A* Visualizer - Python

A* solver for the sliding-tile puzzle generalized to arbitrary board size n, with a Pygame visualization that animates the optimal solution one move at a time. States are bit-packed into a single integer, solvability is settled in linear time by an inversion-count parity check, and Manhattan distance drives the search. The project is built to make one contrast visible: deciding solvability is cheap, while finding an optimal solution is NP-hard for the generalized puzzle, so the frontier grows exponentially in solution depth. Depth-bounded and uniformly random scramble generators demonstrate both regimes, with 5×5 and 6×6 boards showing where A* gives out.

(n²-1)-Puzzle — A* Visualizer

(n²-1)-Puzzle A* Visualizer - C++

A 1:1 C++ port of the Python solver: same board representation, same search, same solvability test, same animation, with raylib in place of Pygame. The packed state needs 125 bits at n=5 and 216 at n=6, which Python's arbitrary-width integers absorb for free, so here it lives in a fixed 256-bit value built from four uint64_t words, copied by value and hashed flat with no per-node allocation in the A* loop. That removes the boxing and collection pressure a managed runtime adds exactly where the search is memory-bound, which is what keeps the larger boards viewable.

Networking, Assignment 1 - TCP Client-Server Architecture

TCP client-server application written on Python's socket library with a custom application-layer protocol layered over the byte stream, supporting text messaging and file transfer. Includes username-based admission, per-connection state tracking on the server, and a directory for uploaded files. Standard library only, with client and server running as two fully independent programs.

Networking, Assignment 2 - Reliable Data Transfer over UDP - Group 15

Stop-and-Wait and Go-Back-N built from scratch on top of UDP, reconstructing the guarantees TCP is trusted for out of the mechanisms that produce them: sequence numbers, acknowledgments, timers, retransmission, and checksums over a channel that loses, duplicates, and corrupts freely. Go-Back-N runs a sliding window against cumulative ACKs on a single timer. Paired with an experiment harness that drives both protocols across controlled loss rates over 360 runs and plots transfer time, throughput, and retransmission counts to make the trade-off measurable rather than asserted.

Networking, Assignment 3 - Routing Algorithms and Simulation

Network-layer routing simulator built around Dijkstra in the link-state model, with Bellman-Ford and a distributed distance-vector implementation added so the choice between them could be defended with measurements. All three are verified to agree on path cost, then compared on running time, memory, routing table generation, and response to topology change across generated networks scaling to 200 routers. Includes a random topology generator with connectivity guaranteed by spanning-tree construction, a socket-based simulation in which every router binds its own UDP port and packets are forwarded hop by hop, and a Tkinter interface with live packet animation, per-router table inspection, and interactive link and router failure.
